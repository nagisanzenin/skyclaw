# Modernization development pilot

This pilot compares the pinned old and modern **core agent runtime**, not the full products. It uses four independent standard-library Python tasks, one attempt per version, fixed balanced A/B order, fresh in-memory memory stores and workspaces, the same coding-plan endpoint/model, three tools and limits. It is development evidence and cannot authorize release. The held-out study remains governed by `docs/modernization/BENCHMARK-PROTOCOL.md`.

Build `crates/temm1e-agent/examples/modernization_pilot.rs` in each checkout; copy that exact instrumentation file into the detached baseline as an untracked example without changing its runtime. Save both executables to distinct paths before another build. Run `pilot.py --baseline PATH --modern PATH --output NEW_DIRECTORY --baseline-commit SHA --modern-commit SHA` with `TEMM1E_ZAI_KEY_FILE` pointing at a private credential file. The script never puts the secret in command arguments or artifacts.

The manifest is written before requests and includes the task corpus, checking code, run order, binary hashes and settings. Checks execute outside the agent; the checking code is not copied into its workspace. Each provider request is recorded before dispatch; each response/error is recorded before return. Missing finishes indicate unknown usage. Runtime-reported usage and independently observed provider usage must be compared, not silently substituted. Provider-hidden retries and billable failed requests can still make actual account consumption unavailable. Baseline adapters do not expose every cache category. A missing metric is unknown.

The pilot disables the V2 classifier and leaves Witness, channels, optional background services and TUI unwired in both versions; self-audit remains enabled. Tool effects and memory are isolated by configuration, not an OS sandbox. It therefore does not test those omitted feature families. Shared provider cache, service load and unavailable model revision remain confounders. Do not treat four related coding scenarios as coverage of the whole product, use pilot examples as the held-out release corpus, or count multiple assertions as independent tasks.

Pilot 02 instrumentation adds an identical 125-second post-turn observation window to both executables, with one second of no in-flight provider calls before declaring quiescence. Foreground latency is recorded separately. Cancelled requests have explicit unknown usage; the recorder does not infer zero from absent responses. The Python process deadline includes this drain window.
