# Runtime model selection and delegated usage

Checkpoint64, September9,2026. Related fixes are batched under the creator's quota-conscious workflow; full final release gates remain.

## Implemented behavior

- CoreRuntime now uses MeteredProvider with its explicit immutable model/pricing snapshot. Success/error/drop reaches the owning budget and parent once; returned CoreResult estimates do not record a second charge. A request with a different model is rejected before admission. Existing explicitly supplied custom pricing remains effective, including unknown registry names. Before regression: failed core call produced0owner records; after1unknown. Provider-internal retries are still logical-call outcomes, not individually measured HTTP attempts.
- AgentRuntime.select_model updates current model/pricing/image capability/effective context from its original configured input allowance, preserving provider route, budget, tools, observer state, runtime policy, tasks and journal. No runtime clone/rebuild or verification HTTP is used. Invalid/zero-capacity identifiers are rejected. With Eigen-Tune local routing enabled, a changed reference model is rejected rather than silently carrying old qualification across it. This does not implement requalification.
- CLI now intercepts `/model`; server uses the same direct selection behavior. Status reads the effective runtime instead of unrelated saved credentials. Selection changes the running Tem instance, not saved defaults; restart returns to configured defaults. Server scope remains the shared runtime, not a new per-chat model profile. Server rejects selection while another Arc user pins the runtime, rather than rebuilding an incomplete replacement. No credential write, validation API call or rollback rewrite occurs merely to select a model.
- Perpetuum keeps one shared ProviderCaller whose route/model binding can change. Calls clone the binding before awaiting; in-flight work retains its old snapshot, future calls use the new one. CLI/server `/model` update that binding with the current owner meter. Concerns, schedules and Cortex/Volition are retained. Other legacy provider-replacement paths and TUI reconstruction are separate boundaries; this is not a claim that all factories were unified.
- Derived requests omit native replay state for another model and its associated signatures; opaque-only empty messages are omitted. Raw persisted history stays intact. Current provider/model metadata is supplied from runtime. The root prompt no longer injects a stale hardcoded model/vision catalog or foreign saved-account configuration as the current connection.

## Limits / release status

Instance model selection is explicitly temporary, including server behavior which previously rewrote saved defaults. Native response adapters still own endpoint-bound replay validation. Unknown capability/pricing is not proof of account access or free billing. Perpetuum's existing timeout/output policy and generic provider replacement are not comprehensively redesigned here. Core output/history-loop policy remains legacy; this change addresses accounting, not a complete specialist scheduling redesign. Observer configuration-mode/intervention semantics and legacy growth/cloud/telemetry findings remain documented work rather than falsely completed features. Broader frozen A/B, final entrypoint/migration/platform and release gates have not passed; no version bump, main merge or release.
