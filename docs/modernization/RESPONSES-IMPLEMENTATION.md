# Stateless Responses transport and replay

Implementation checkpoint dated 2026-09-08. Direct OpenAI transport and Codex subscription transport now share a Responses codec, byte framing and completion collector. Credentials remain in their original transport; there is no automatic fallback from a subscription endpoint to a metered API.

## Why the previous adapter was insufficient

The Codex collector discarded response IDs and usage. Its SSE reader decoded each network chunk lossily, had no aggregate bounds, accepted truncated tools as `{}`, and could dispatch accumulated calls before a terminal response. It logged request bodies and non-text event bodies. Request conversion discarded all but one system instruction and rewrote optional tool fields into required fields while claiming non-strict schemas.

Responses is also a conversation protocol. Flattening output to text/tool triples loses encrypted reasoning, original item order and assistant phase. [OpenAI's migration guide](https://developers.openai.com/api/docs/guides/migrate-to-responses) describes the item-based request format. Its [reasoning guide](https://developers.openai.com/api/docs/guides/reasoning) documents replay of output items in stateless mode, including encrypted reasoning and original assistant phase. [Astra guidance](https://developers.openai.com/api/docs/guides/latest-model) requires Responses for tool calling and excludes sampling parameters used by older Chat Completions models.

## Implemented contract

- Exact catalog metadata selects native `/responses` for direct OpenAI Astra, GPT-5.6 Sol/Terra/Luna (including the explicit Sol alias), GPT-5.5 and GPT-5.4. Other routes retain their existing protocol. These are documented endpoints with fixture acceptance, not proof that any particular user's account can access a model. Existing saved model selection remains unchanged.
- Requests preserve all system segments, tool schemas and tool-result IDs. Native API requests send the caller's output limit. Codex backend requests omit unsupported output-limit and sampling parameters. Both use stateless replay. The generic temperature setting is not forwarded on these native reasoning routes.
- `ContentPart::ProviderState` retains the original output array, response ID, provider route and model. The normalized text and function calls remain available to Tem's runtime. Same-route/model replay sends the original array once. Different routes/models receive normalized conversation content without opaque state. This is route/model binding, not proof of cross-account encrypted-state portability.
- Native and normalized tool history must agree; pruned/edited history cannot resurrect a call through hidden replay state. Historical tool results must match unique preceding calls. If Witness or redaction changes the delivered reply, replay retains the original wire state plus the delivered correction as assistant content.
- Native state is not transcript text, a tool request, or quoted compaction evidence. It is included in history serialization and conservative context-size accounting. Successful final replies retain it in runtime history. The raw source remains available when context is compacted; compaction itself deliberately creates a reduced provider view.
- Shared SSE framing handles split UTF-8, LF/CRLF/CR, comments and multiline data. The transport caps each event at 2 MiB and the wire response at 64 MiB. The collector caps retained normalized/native output at 32 MiB. The Responses decoder caps visible text and aggregate argument deltas at 16 MiB each, individual arguments at 2 MiB, function streams/calls at 128 and output items at 1,024.
- Only a validated `response.completed` authorizes tool calls. Failures, incomplete responses, EOF, malformed JSON, invalid tool arguments, contradictory terminal data, duplicate/out-of-order sequence numbers and orphan argument deltas fail without fabricating tool input or successful completion. Commentary-only output without a tool request is not accepted as a final answer. Unsupported hosted/custom output item types return an explicit error.
- Actual text deltas reach the TUI observer. Terminal usage is normalized and retained, including cache reads; missing usage remains unknown. Codex 429 responses preserve a supplied retry delay and remain subscription rate/plan errors. Request/event bodies and raw streaming error bodies are not logged or surfaced by these paths.

## Acceptance evidence

Unit fixtures exercise byte-by-byte Unicode, strict argument decoding, incomplete/repeated events, native JSON persistence and replay, preserved optional schemas, cross-route state exclusion and commentary/final distinction. Real local HTTP tests cover direct OpenAI route selection and a two-request tool round trip, plus redacted error reporting. Runtime integration verifies final native state survives in history without appearing in the user reply. This does not use or mutate an actual Codex account.

A regression smoke through the real TUI bridge using the authorized Z.ai coding plan returned exactly `maple-7319 / amber` in 5.8 seconds, with 6 real deltas and reported usage of 6,405 input / 49 output tokens. Durable final UI-event acceptance and foreground shutdown passed. The optional Engram curator was canceled after the shutdown drain deadline; its usage/effects remain unknown. The saved log predates a cosmetic smoke-output fix and still contains the old numeric `$0` compatibility projection; the runtime billing record correctly states subscription/unknown charge. This is a focused regression check, not a held-out A/B result or PTY/rendering acceptance.

## Remaining boundaries

Live OpenAI/Codex account acceptance is not established by fixtures. Dynamic provider model discovery, modern model menus/defaults, explicit reasoning controls, provider-native compaction, hosted tools, async tool calling and WebSocket steering remain separate work. Opaque state is not yet provided by Anthropic/Gemini adapters. Prompted JSON tool mode retains its older text-history behavior. The shared durable usage ledger must still cover canceled and background calls before total cost/quota accounting is complete.

Endpoint binding follow-up: the direct OpenAI route identity includes its normalized endpoint origin and path. Changing `base_url` therefore prevents replay of the previous endpoint's opaque state even when the provider/model names remain the same. URL userinfo, query and fragment are not stored in that identity. Unknown provider names require an explicit destination instead of inheriting OpenAI's default URL.
