# TUI transcript restoration and bounded history pages

`ExecutionJournal::conversation_page` reads the committed head in one database transaction without acquiring a conversation turn or changing busy/delivery state. A 100-message page hydrates only the selected content-addressed manifest entries with the existing integrity checks. Legacy inline heads remain readable within the 32 MiB/100,000-message limits. Cursors bind scope, epoch, revision and preceding index; a changed head requires an explicit latest-page refresh, preventing mixed sessions or duplicate/gapped pagination.

TUI startup restores visible normalized history. `/history` reloads the latest saved page; `/history-more` prepends an older page without calling a model. Restored native reasoning/signatures never render. Individual messages display at most 8,192 characters with an explicit excerpt notice, tool calls/results use compact saved-content descriptions, and restored page windows retain at most 1,000 rendered messages. Full source history remains in canonical storage. Unknown historical token costs/timestamps are not presented as measured usage. Interrupted turns and unresolved reply delivery are identified explicitly; rendering a saved reply is not a delivery acknowledgement. Session reset/import/recovery confirmation refreshes the saved view. A queued startup restore cannot erase a user submission already in progress.

Validation includes scoped paging, stale cursor rejection, reading during a busy turn without clearing the marker, opaque-state non-disclosure, Unicode excerpt bounds, and a startup/input race. Real Unix PTY acceptance closes and reopens the same profile and verifies the original user/assistant text with zero provider requests, alongside terminal resize/restore and onboarding exit. These checks do not constitute Windows PTY acceptance or proof that all saved tool results represent successful goals.
