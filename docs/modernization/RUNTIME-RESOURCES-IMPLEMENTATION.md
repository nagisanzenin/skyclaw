# Runtime resource binding — checkpoint45

## Defect and implemented contract

The root entrypoints reconstruct AgentRuntime after model/provider/tool changes but reuse tool instances. InvokeCoreTool stores its original provider, model, budget, pricing and memory. SpawnSwarmTool reads an initially populated shared context. Thus a new foreground runtime can delegate using stale model/account resources. Updating a global shared provider would also let another active turn change underneath the caller.

The core contract now provides an immutable `RuntimeResources` snapshot: provider handle, model ID, effective context limit, captured pricing, owning budget, memory and feature policy. The budget implementation and policy data definition move into core without changing formulas/defaults; agent re-exports preserve existing import paths. This avoids introducing a core-to-agent dependency cycle or an untyped Any resource bag.

The Tool trait has an optional synchronous binding hook. Ordinary tools retain their instances; tools that launch model work return a new instance bound to the supplied resources. AgentRuntime binds the effective tool list from its own snapshot; invocation does not mutate shared original tools or clone AgentRuntime/BackgroundTasks. InvokeCoreTool binds its provider/model/pricing/budget/context/memory. SpawnSwarmTool retains its Hive startup handle but overrides execution resources in a local snapshot before starting workers; its shared handle is not rewritten. Child AgentRuntime construction then binds its own tools again to the child's budget/policy.

## Remaining limits

This is an execution binding contract, not full AppServices composition, durable accounting/reservations, OS sandboxing, complete immutable capability resolution or release acceptance. Bound tools retain their existing tool templates/recursion and permission policies; new principal namespaces and arbitrary inherited filter contracts are separate work. Pricing/model catalogs are still resolved in other consumers and can change outside this snapshot. Consciousness, Perpetuum/EigenTune lifecycle wiring and typed durable goals/evidence remain separate work. Direct embedded-host calls retain explicitly constructed legacy resources. CoreRuntime provider errors/cancellations still need the same metered outcome lifecycle used by auxiliary consumers; this binding change makes no complete-accounting claim.
