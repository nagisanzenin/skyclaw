## Thirteenth implementation checkpoint (Git snapshots)

Snapshot creation and restoration now operate through a private index, preserving the user's staging area. Captures retain tracked and non-ignored files, exclude `.temm1e` bookkeeping, and pin their trees under Git refs so garbage collection does not discard them. Restore captures and registers a recovery snapshot first, restores deleted files, and removes newer non-ignored files. Snapshot metadata is replaced atomically and a stable lock excludes concurrent Tem snapshot operations. Requests from a repository subdirectory fail explicitly instead of changing files outside the tool workspace. Git subprocesses use bounded output and owned cancellation.

Direct integration coverage preserves the original index bytes, separates staged and unstaged file content, verifies create/delete restoration, retains ignored files and metadata, and restores the automatically saved recovery snapshot. Git worktree updates are not a crash-atomic multi-file transaction; the retained recovery snapshot makes prior contents available but automatic interrupted-restore reconciliation remains open. Sparse checkouts, dirty submodules and external concurrent Git writers need additional acceptance checks. This is not a complete filesystem backup. Git semantics: https://git-scm.com/docs/git-read-tree and https://git-scm.com/docs/git .
