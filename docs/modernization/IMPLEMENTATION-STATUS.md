## Second implementation checkpoint

The default remains `~/.temm1e`. Explicit paths and workspace/system configuration retain their existing meaning; this is not a sandbox. See [isolated profiles](ISOLATED-PROFILES.md).

Tool rows are compact by default; Ctrl+T expands/collapses details, Ctrl+O controls the optional activity panel. Provider text streaming and broader interaction polish remain unfinished.

- README is reduced to 100 lines, with a linked feature guide, CLI reference and preserved historical release notes. Eighteen matching concept images follow the creator's art direction and omit numerical performance claims.

## Third implementation checkpoint

- Slack uploads now allocate an external upload URL, transfer bytes without the bot token, then finalize the file with its channel and caption. HTTP failures stop the sequence; URL downloads and byte uploads enforce a 100 MiB application limit. Local HTTP fixtures verify all three requests and that a failed byte upload never finalizes. No live Slack messages or files were sent. See Slack's [allocation](https://docs.slack.dev/reference/methods/files.getUploadURLExternal/) and [completion](https://docs.slack.dev/reference/methods/files.completeUploadExternal/) contracts. History pagination and ambiguous-outcome reconciliation remain unfinished.
- Perpetuum estimates activity from matching weekday/hour slots across the previous four completed weeks, including inactive slots after its first recorded day, in the configured timezone. A Beta(1,1) prior prevents sparse observations from producing certainty. Tests cover inactive slots, weekday, timezone, stale observations and absent history. This estimates recorded activity, not online presence; existing UTC-hour buckets limit precision for fractional-hour timezones.
- Focused checkpoint regression: 69 channel tests with Slack enabled and 80 Perpetuum tests pass. These overlap prior totals and are not additional independent workspace coverage.

## Fifth implementation checkpoint

- An execution journal records the scoped turn and tool intent before dispatch, then records the tool result separately. CLI/TUI and their 25 CLI/server construction/rebuild sites enable it. Cancellation drops in-flight runtime futures, records unknown outcomes for unconfirmed tool calls, and saves TUI history on error paths. Tests exercise restart persistence, cross-user isolation, duplicate operation IDs and token/legacy-flag cancellation through the real runtime. The journal deliberately uses `reply_returned`, not `completed`; recovery leases, reconciliation, delivery outbox and goal verification are still unfinished. Detached background jobs are not yet covered by turn cancellation.
- Automatic Engram curation now writes user-scoped facts and cannot overwrite a visible global fact. Existing global records are preserved pending an explicit migration strategy. Broader channel/principal namespace isolation remains unfinished.
- Self-audit accepts only an exact completion marker and preserves corrections/retractions instead of replacing them with the original unsupported claim. Its historical `FailedOpen` telemetry label remains for unconfirmed audits. Model confirmation is not independent evidence.
- Witness predicate checks and commands without an explicit working directory use the actual turn workspace rather than the process startup directory. Behavioral assertions can satisfy code verification without inventing a requirement to put tests in the implementation file. Verification exceptions honor the configured narrative strictness and disclose unavailable verification. LLM tier wiring and grounded evidence payloads remain unfinished.
- OAuth refresh/login/logout share a stable OS file lock. Refresh reloads current credentials under that lock, logout invalidates cached credentials locally, and an interrupted/ambiguous rotation leaves a marker requiring reconnection rather than blind refresh-token reuse. Explicit rejection clears the marker. Unix private modes are checked locally; Windows behavior still needs platform validation. Local fixtures verify one refresh across independent stores; no real OpenAI account refresh or logout was performed.

- GLM-5.3-Flash uses its documented 1M context / 128K output limits and image capability. Runtime final budgets honor custom model limits. Compatible providers retain their configured identity so custom limits and subscription labels resolve correctly. Subscription usage is no longer displayed as a zero-dollar bill; API cost labels explicitly describe estimates. Complete pricing/catalog unification remains unfinished.
