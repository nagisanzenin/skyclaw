# Durable goal and evidence foundation

Checkpoint46 connects typed goal state and bounded evidence to the active ExecutionJournal. This is the foundation for P02/P03; it does not claim a completed persistent queue, goal evaluator or automatic pursuit policy.

## Implemented behavior

Every newly admitted durable execution creates a goal record in the same SQLite transaction as its inbound claim and original checkpoint. The original inbound text is retained verbatim, with a 1 MiB bound that fails admission and rolls back the claim instead of truncating the user's objective. The record stores schema version1, execution scope, authenticated user/role snapshot and the canonical conversation access domain when that execution belongs to an admitted conversation. A request is recorded without assuming its text is a fully specified task contract.

Goal state and execution state are separate. Admission saves `running`. Returning a reply saves `awaiting_evidence` with an explicit unverified reason; interrupted/failed execution saves `recovering`, requiring effect reconciliation. A terminal execution transition and its goal revision/event commit atomically. Two concurrent terminal updates cannot both advance the revision. Nothing in this checkpoint infers `succeeded` from DONE text, tool output, a reply being returned or outbox delivery. A saved running state is historical, not a live lease.

Tool intent appends an event with the operation ID, tool and arguments hash. Recording a result atomically resolves the existing operation, stores immutable content-addressed evidence and appends its event. Evidence contains tool/operation identity, error flag, original byte count/hash, bounded UTF-8 output and an explicit truncation flag. It hashes the serialized snapshot including provenance; the original full-output hash does not make omitted content available. The existing 65,536-byte output prefix and truncation notice are preserved. JSON escaping is bounded to512KiB, event metadata to8KiB. Duplicate result replacement fails. Unknown operations have no fabricated result evidence.

The additive schema transaction creates goal version/record/event/evidence tables. Existing execution/history/outbox rows are neither rewritten nor promoted into goals. Unknown goal schema versions are rejected without downgrading their version. Legacy raw execution APIs continue to operate without inventing missing goal records. These changes are not a destructive data migration; no extra full database copy is made on this storage-constrained host.

`/goal-status` is a read-only command in the common owner-command handler used by CLI/server/TUI, with a TUI menu entry. It shows up to20records and512-character objective previews, evidence counts and uncertain-operation counts. Control characters in previews are escaped; original stored objectives stay unchanged. Scope checks use the authenticated conversation domain and canonical configured workspace. CLI/TUI currently use the existing profile/workspace default; changing the shell's current directory is not changing that workspace. Existing command role restrictions remain unchanged. The evidence resolver also requires this scope and verifies the snapshot hash before decoding it.

Core types define Criterion, Assessment, evaluator kinds, outcomes and a non-vacuous assessment helper. No required criteria, missing/duplicate/unknown criteria, missing/unresolved evidence, missing evaluator version or a model assessment substituted for a deterministic evaluator cannot pass. A passing build criterion does not erase a failing behavior-test criterion. These contracts are tested but **are not yet wired to persistent criteria, Witness or a succeeded transition**. The active ledger accurately remains unverified until that integration exists.

## Validation

The pre-change journal test failed because no typed goal_records table existed, even after an execution returned prose claiming DONE (`implementation-goal-ledger-before-test.log`). Existing execution state already distinguished reply_returned; the new feature adds durable goal/evidence state without misrepresenting that earlier protection.

After implementation780agent unit tests,280core tests(one ignored) and all64agent integration tests pass. New tests cover original objective/reopen, 1MiB admission rollback, bounded Unicode evidence, duplicate-result rejection, foreign access domain, tamper detection, ordered intent/result/return events, one winner among concurrent terminal transitions, future schema rejection and legacy non-promotion. Evidence/criteria tests do not substitute for real task evaluation.

The actual CLI fixture creates an artifact via file_write, receives a synthetic false prose claim that tests passed, and verifies the saved goal remains awaiting_evidence. SQLite inspection confirms original objective, one evidence snapshot/hash and ordered events. Restart inspection makes zero provider calls. A synthetic journal copied to a different profile/workspace reveals zero goal records through the new workspace's command. All traffic is localhost:3requests including the optional blueprint response. See `scripts/goal_ledger_smoke.py` and `implementation-goal-ledger-cli-smoke-v2.log`.

Actual Unix PTY goal inspection also passes during model-switch chat and after restart, makes no extra provider calls, and restores exact terminal attributes after resize/exit (`implementation-goal-ledger-tui-smoke.log`). The shared fixture adds an optional goal_check, preserving earlier scenario behavior.

Failures are retained. Initial SQLx raw_sql-with-transaction initialization caused a Send/Executor lifetime compile error; a temporary boxed future localized the error but did not fix it. Static DDL now executes as individual parameterless queries inside the same transaction; boxing was removed and tests pass. Logs are library-tests/v2(failure)/v3(pass). The first CLI fixture expected its artifact in the process cwd, contrary to Tem's existing profile/workspace contract; corrected to that actual workspace and tested a different profile for isolation. This was a fixture error, not a change to workspace defaults. Root79tests,14root integration and50TUI tests pass. Full workspace/all-feature/all-target clippy passed1m47s and cleaned3.8GiB (`implementation-goal-ledger-workspace-clippy.log`); existing dependency future-compatibility notice remains.

## Next implementation and limits

Persist immutable criteria revisions and assessments bound to the original objective and exact evidence references. Connect the actual per-turn Witness Oath/verdict, preserving user requirements, evaluator version/type and inconclusive failures. Do not permit a model-authored criterion to silently replace a user requirement, or equate passing a weak declared check with complete coverage. Expose missing criteria and evaluation separately. Add goal transitions only with a compare-and-swap revision and complete required evidence; never retrofit legacy prose as success.

Then connect priority/lease/generation ownership, explicit cancellation/quota states and reconciled continuation to the task queue. D02 still gates default automatic pursuit/stopping changes. Child Hive/Core executions need durable lineage and criteria/evidence linkage; a recorded parent tool result is not the full child journal. This checkpoint adds no model call or background continuation, does not close D01 principal namespace/multi-user concerns, and does not implement total retention/GC, backups, crash recovery leases, a tamper-resistant external trust anchor or full release acceptance.
