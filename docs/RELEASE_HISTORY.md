2026-05-15  v5.6.1  ●━━━ CLI multi-line input — fix line-buffer fragmentation. **Bug** (surfaced during internal A/B testing of GH-62's Self-Audit Pass): the CLI channel at `crates/temm1e-channels/src/cli.rs` treated every newline on stdin as a message boundary, fragmenting any multi-line prompt into N separate inbound messages — one per non-empty line — each triggering its own full agent loop (classifier, system-prompt assembly, LLM call, response). Pasting code into `temm1e chat`, piping a multi-paragraph prompt, or sending a heredoc all silently shredded into pieces; the agent received the first paragraph alone, replied "what about the rest?", and subsequent lines arrived as orphaned turns. Telegram/Discord/Slack/WhatsApp don't have this issue — every other channel submits the user's whole message as one atomic blob; only the line-buffered CLI was affected. Cost was N× (one full pipeline per line), and the classifier itself logged "incomplete/malformed" warnings on the fragments — the system noticed but had no way to merge messages back. **Fix**: two new slash commands and an EOF auto-flush, fully backwards-compatible. (1) `/paste` enters multi-line buffering mode — subsequent lines accumulate verbatim (indentation preserved, blank lines preserved) until `/send`, `/quit`, or EOF. (2) `/send` submits the accumulated buffer as one InboundMessage. (3) EOF on stdin while in paste mode automatically flushes the buffer as a final message — useful for piped scripts that omit `/send`. Single-line behavior is unchanged: typing `hello\n` still submits "hello" as one message; existing single-line automation (`echo "msg" | temm1e chat`) is byte-identical to before. Refactored into a pure `CliInputState` state machine (`handle_line` + `flush_on_eof`) — fully unit-testable without touching stdin/stdout. **Files**: `crates/temm1e-channels/src/cli.rs` (state machine + 12 new tests), `src/main.rs` (`/help` text adds `/paste` and `/send` entries). **Regression fence**: 12 new unit tests covering single-line unchanged, empty-line normal-mode, `/quit`/`/exit`, `/paste`→`/send` atomic submission, indentation and blank-line preservation, EOF flushes pending buffer, EOF without paste returns None, EOF with empty paste returns None, `/send` outside paste returns Info, `/quit` in paste discards buffer and exits, `/paste` inside paste is warning (buffer preserved), `/file` missing path returns FileNotFound. 25 crates, 2,889 tests, 0 failures, 0 clippy warnings, 0 fmt drift. Cross-channel parity preserved — Telegram/Discord/Slack/WhatsApp unchanged.

2026-05-03  v5.6.0  ●━━━ Persist through multi-step tasks — closes GH-62 (dsiMJ). **Bug**: the agent loop terminated whenever the LLM emitted a turn with no tool_use parts (`crates/temm1e-agent/src/runtime.rs:2009-2010`). Flagship models (Claude / GPT / Gemini) honor an implicit "say-it-or-call-it" contract — if they say "Let me X", they emit the X tool call in the same turn. Smaller open-weight models (Qwen 27B / 35B-A3B in dsiMJ's report) routinely break that contract by emitting "Let me check the file" as plain text and forgetting the tool call. The loop saw `tool_uses.is_empty() == true`, treated the turn as complete, and the worker correctly flipped `is_busy = false` (`src/main.rs:5998`); `/status` correctly reported "Idle" because the worker really WAS idle. The bug wasn't in the status reporting — it was the missing verifier between "no tool call" and "task done". **5-phase fix, ONE release**: (A) **`file_read` truncation visibility** in `crates/temm1e-tools/src/file.rs:90-141` — now emits a header AT THE TOP plus the existing footer when EITHER 32KB byte cap OR line-limit truncates: `[TRUNCATED — showing lines 1-N of TOTAL. To continue, call file_read with offset=N+1]`. Also fixed a latent bug where the byte-cap path's shadowed `end` variable hid the line offset from the partial-read footer trigger. (B) **Explicit "say-it-or-call-it" contract in stable system prompt** at `src/main.rs:440` — added a new `END-OF-TURN CONTRACT` block teaching the model that intent without a tool call leaves the user waiting forever. Lives in the cacheable stable base, not the volatile tail (`runtime.rs:1378-1454`), so prompt-cache hits stay valid. (C) **`is_compound_task` upgraded from keyword to LLM** — old `done_criteria::is_compound_task()` (English action verbs, "and"/"then" connectors, numbered lists) renamed to `is_compound_task_fallback`; primary path now derives from `llm_classifier::TaskDifficulty != Simple` (already computed once per message at `runtime.rs:1075`). Zero extra LLM round-trip; respects `feedback_no_keyword_matching.md`; covers single-verb requests like "check server.py for the blueprint endpoints" that the keyword path missed. Falls back to keywords when v2_optimizations is disabled. (D) **Self-Audit Pass** in new `crates/temm1e-agent/src/self_audit.rs` (~200 lines, 9 unit tests) — when the loop is about to exit via `tool_uses.is_empty()` AND tools were available AND text was produced AND the audit hasn't already run this turn, push a synthetic `[__INTERNAL_AUDIT__]` user message asking the model to either confirm completion (`[DONE]`) or commit to the tool call it skipped, then `continue` the loop. Hard cap of 1 audit per turn enforced at the branch condition (cannot infinite-loop). Per the One Model Rule (`feedback_one_model_rule.md`), the audit uses the same active provider+model as the main loop — no cheap-classifier fallback, no provider auth complexity. The `[DONE]` token never reaches the user: a `pending_audit_pre_text: Option<String>` cache holds the original text and swaps it back at exit. Fail-open on malformed audit responses — degrades to today's baseline, never a regression. Cost-cap gate skips audit if it would exceed `max_spend_usd`. **Default OFF in v5.6.0** (opt in via `[agent] self_audit_enabled = true`); flip ON in v5.7.0 after telemetry from Phase E confirms <2% trigger rate on flagship models. (E) **Per-(provider, model) discipline telemetry** — new `model_discipline` SQLite table in `crates/temm1e-memory/src/sqlite.rs` with columns `text_only_exits`, `audit_done_responses`, `audit_tool_call_responses`, `audit_failed_responses`, `audit_skipped`, `last_updated`. Two new `Memory` trait methods (`record_audit_outcome`, `get_model_discipline`) with default `Ok(())` impls so non-Sqlite backends (markdown, mock, failover) don't break. Observability-only in v5.6.0; feeds adaptive auto-disable in v5.7.0+. Telemetry call inside the audit hook is fire-and-forget via `tokio::spawn` — never blocks the user reply. **Wiring fan-out**: `self_audit_enabled` field added to `AgentRuntime` (defaulted `false` in `new()` and `with_limits()`), `AgentConfig` (defaulted `false`), threaded through 23 `with_limits` construction sites in `src/main.rs` plus 1 in `crates/temm1e-tui/src/agent_bridge.rs`, surfaced via `with_self_audit_enabled(bool)` builder. **Provider-agnostic invariant honored**: works identically across Anthropic, OpenAI, Gemini, Grok, OpenRouter, MiniMax, Z.ai, Qwen — the audit is one extra LLM round of the same provider; no provider-specific code paths. **Future-proofing**: future small models (Mistral-Tiny, Qwen-7B) get caught by the audit; future flagship models (Claude 5, GPT-6) emit `[DONE]` instantly and Phase E telemetry can auto-graduate them out of auditing; future reasoning-heavy models (DeepSeek R3, GPT-o5) are already handled by the GH-49 reasoning-fallback path AND now get the audit safety net for stalled-promise reasoning leaks. **Regression fence**: 23 new tests — 4 unit tests in `file.rs` (line-limit header/footer, byte-cap header/footer, no-truncation no-header, byte-cap offset math), 9 unit tests in `self_audit.rs` (marker prefix, [DONE] classification with surrounding text, tool-call override, malformed/empty fail-open, audit-message filter, outcome-to-kind round trip), 7 integration tests in `crates/temm1e-agent/tests/self_audit_integration.rs` using a new `QueuedMockProvider` (catches stalled promise → 3 provider calls; [DONE] serves pre-audit text; fail-open exits with original; disabled = exactly 1 call; no-tools skipped; hard cap = exactly 2 calls cannot loop forever; telemetry recorded), 3 sqlite tests (counter increments, none-for-unseen, concurrent-write safe). 25 crates, 2,878 tests, 0 failures, 0 clippy warnings, 0 fmt drift. Parity smoke (CLI + TUI + server) all anchors green. Credit: @dsiMJ for the clear repro on issue #62 with model details (Qwen 3.5-27B, 35B-A3B), and the precise transcript showing "Let me look at server.py..." → silent agent → user manually waking it up — that pattern made the diagnosis trivial.

2026-04-21  v5.5.3  ●━━━ GH-59 fix: MiniMax / strict OpenAI-compat backends now work after memory builds up. **Bug** (reported by @GezaBoi): MiniMax API returned `invalid params, chat content has invalid message role: system (2013)` after a TEMM1E session had been running for a few hours, and **a full reinstall temporarily fixed it** — until memory built up again and the error came back. **Root cause**: `crates/temm1e-providers/src/openai_compat.rs::build_request_body` was the only provider that let `Role::System` messages leak into the OpenAI Chat Completions `messages` array mid-conversation. It prepended one system message from `request.system_flattened()` at position 0, then naively iterated every entry in `request.messages` — including `Role::System` — and converted each one to `"role": "system"` in the JSON body. `crates/temm1e-agent/src/context.rs:535-543` assembles the outbound list as `summary_messages + digest_msg + blueprint_messages + lambda_messages + kept_older + recent_messages`, and the first four buckets all push `Role::System` entries (10 injection sites across context.rs for λ-memory, blueprints, knowledge, learnings, tool reliability, chat digest, dropped-history summary; plus DONE-criteria at `runtime.rs:1210`). On a fresh install those buckets are empty — one system message goes out, MiniMax accepts. As memory builds, multiple `role: system` entries pile up interleaved between user/assistant messages, and **MiniMax correctly rejects it per the OpenAI Chat Completions spec** (single leading system message). OpenAI, Grok, OpenRouter, Z.ai accepted the multi-system shape leniently — so the bug lived undetected for multiple releases. **Why the other providers didn't hit this**: `crates/temm1e-providers/src/anthropic.rs:94` already `.filter(|m| !matches!(m.role, Role::System))` and uses only the top-level `system` field; `crates/temm1e-providers/src/gemini.rs:190-207` pattern-matches `Role::System` and accumulates into `systemInstruction`, never `contents`; `crates/temm1e-codex-oauth/src/responses_provider.rs:55,68` extracts system content the same way. OpenAI-compat was the outlier. **Fix** (`crates/temm1e-providers/src/openai_compat.rs::build_request_body`): (1) collect `request.system_flattened()` base + volatile into a `system_parts: Vec<String>`; (2) iterate `request.messages` once, pull text out of every `Role::System` entry (both `MessageContent::Text` and `MessageContent::Parts`), append to the same vec; (3) emit a single `{"role":"system", "content": parts.join("\n\n")}` at index 0; (4) skip `Role::System` in the main conversion loop so no mid-list system messages leak through. Write-order preserved so content semantics are identical — the LLM reads the same text, just in one system message instead of many. **Impact matrix**: MiniMax users go from broken-after-memory-builds to working indefinitely; Gemini's OpenAI-compat endpoint gains the same safety; OpenAI/Grok/OpenRouter/Z.ai users see zero behavioral change (they already accepted the lenient shape and the spec-correct shape is identical content-wise); Anthropic + Gemini native + Codex OAuth untouched. **Prompt caching**: the OpenAI-compat prefix was never cache-stable in the first place (λ-memory / chat digest / volatile system change every turn), so merging doesn't degrade anything; Anthropic's split-block caching is a different codepath. **Regression fence**: two new unit tests in `openai_compat::tests` — `build_request_body_consolidates_multiple_system_messages` constructs a request with base system, volatile system, and three mid-list `Role::System` entries (simulating dropped-history summary + blueprint + λ-memory) plus user/assistant turns, and asserts **exactly one** `"role":"system"` at index 0 with all content merged write-order, plus user/assistant ordering preserved; `build_request_body_merges_midlist_system_when_base_absent` covers the `request.system == None` path where the only system content lives in `messages`. Both tests would have caught this the day λ-memory landed if they'd existed. 25 crates, 2,836 tests, 0 failures, 0 clippy warnings, 0 fmt drift. Credit: @GezaBoi for the clear repro on issue #59.
